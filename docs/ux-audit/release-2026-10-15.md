# UX release reconciliation — 15 October 2026

The UX audit and its original verification used GitHub commit `1b583b61b75d7585e73c9ca90d6837b27d54c255`. Before release, the native Sites source was found at version 83, commit `85f8243f08dc5605e7c503d593fc9edc9ce67e04`. It includes newer dish/menu review, purchasing details, production tasks, approved production handoff, current-menu scope, and migration 0020. Publishing the original audit branch directly would remove those changes.

The release combines both histories. It retains the current Sites functionality and applies all 31 UX fixes to those screens. Native Sites remains the deployment destination; GitHub remains the development source. A source push is separate from publication.

- The current menu editor remains intact. Its responsive review panel has 858 px for the detail at a 1100 px viewport, compared with the original audit's clipped 168 px editor. Browser geometry checks cover 320, 360, 390, 768, 1024, 1100, 1280, 1440, 1535, 1536 and 1600 px, with no horizontal control clipping.
- Main navigation, selected dish/variant, date, search, catalog type/review filter and current/all-menu scope use the shared URL/history controller. A late callback from inactive daily work cannot replace the current section. The new editor keeps its local state while another section is selected.
- The Ingredients heading and main action precede preparation actions, filters and results. Preparation and Batch details are at y=237 px on 390×844 with 100 local synthetic items. The first analysis card is at y=526 px. The measured Morning task is at y=558 px; the actual Finish → Morning run also keeps the first task in the first viewport.
- Ingredient Undo applies to the current notebook. It restores the removed input without replacing later edits. Review/completion flags are restored only when the recipe still exactly matches the result of the removal. Server revisions and existing save receipts remain authoritative.
- Same-tab review, preparation validation and Back, explicit station changes, calendar differences, focus restoration, draft protection and touch targets work with the newer screens. Add dish and Duplicate dish also use the shared dirty-form dismissal confirmation. Numeric fields forward field-level accessibility attributes to their actual inputs.

All 31 IDs remain mapped in [status.json](status.json), with links to the current release evidence. The original report and evidence remain historical records of the audited baseline.

## Publication boundary

Release targets the existing project `appgprj_6aa56065ff148191bca78164158e3a4c`, preserving its public Sites access policy and existing D1/R2 bindings. The release archive contains production `dist/` output only, including its hosting metadata and migrations; local D1/R2 state and synthetic fixtures are excluded.

The cloud skill registry did not expose the normal Sites source helper. The fallback uses a short-lived native source credential passed over stdin, kept in process memory only, a non-force Git push with a live-source revision check, a clean committed source build and a dist-only archive. Version saving and production publication use native Sites tools. No credential is written to disk or Git configuration.

The managed cloud network proxy rejects direct access to the production origin with CONNECT 403. Local browser evidence is therefore not an authenticated production smoke test. Publication success, version/commit identity and preservation of the access policy must be verified with native Sites responses; the final release receipt is kept outside the deployable source tree.
