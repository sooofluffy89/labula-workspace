# Authenticated stock activity and kitchen team

Adds an append-only kitchen_activity ledger written atomically with stock settings, all evening commands and Morning Ready/Undo. Confirmation-derived task create/reopen/cancel events are marked system; catalog merge/undo effects are recorded by SQL triggers. Stable dispatch actor IDs and server-generated actor snapshots are authoritative. Optional client click metadata survives exact retry/recovery and is marked unverified in UI. Legacy commands are parsed unchanged with unknown client time. Explicit reviewed reapplication gets a fresh click timestamp and a reference to the rejected operation.

Team profiles support owner-managed kitchen names and stock-write pause, plus pending verified-email binding on first sign-in. Existing permitted users automatically receive a profile; private Sites access remains the access boundary. Creating a profile sends no invitation. Paused accounts cannot make new stock/evening writes, including through old clients and races; exact already-committed receipts can still be recovered. Owner pause is prohibited. These restrictions do not revoke recipe or review access: remove site sharing for that. Historical names are immutable. No application impersonation or PIN authentication was added.

Activity & team is separate from the compact work list. Saved events have stage/person/item/saved UTC date filters and stable cursor pagination. Display uses Prague time; owner CSV includes raw UTC timestamps, IDs, before/after state and source. Export pins server-time and committed-row upper bounds, paginates all rows and fails without partial download above 100,000 events. New activity starts prospectively; old tables are retained without fabricated backfill. Private backup includes all 21 tables.

Verification: check-all (44 scripts), types, lint, build, synthetic browser workflow. check-stock-activity executes real APIs against SQLite migrations: owner authorization, binding, pause and race, append-only triggers, atomic rollback, exact retry, legacy time unknown, Ready/Undo vs automatic effects, pagination, CSV formula escaping and untouched recipes. Existing evening/stock suites exercise catalog merge/undo and uncertain saves.

New migration 0009 only adds three tables, indexes and auditing triggers. No existing rows are rewritten or deleted. Preserve migration metadata after deployment. Rollback should be forward-fix; an older backend would cease producing the new detailed events even though stored data and receipts remain compatible. Do not roll back a database over live kitchen changes.

Limits: author means the signed-in person who submitted the status, not proven physical producer. Device time is not trusted. No active-work timer, quantity tracking, task assignment, service deadline alerts or staff performance scoring. No worker profile is prefilled for actual staff beyond authenticated registration. Site sharing stays unchanged.
