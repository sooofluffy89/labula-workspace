# Manage list: table with instructions

Implementation based on `navrh-manage-list-semafor-2026-10-02/master-prompt.md`, baseline ecc1d24 / Sites v62. Publication identity and production data comparison are recorded outside the source checkout in `manage-list-release-2026-10-02/REPORT.md`.

## Behavior and scope

Manage list shows the canonical ingredient catalog, including stock-excluded items. Displaying these items does not restore membership or tracking. Owner/Manager can configure frequency and station while Track is Off; explicit On restores membership in the same atomic transaction when necessary. All existing search/alias, kind, group, multiple menu categories (OR), tracking, frequency, instruction and station filters, saved personal views, grouping and bulk station assignment remain available. Frequency filtering uses the prepared round even for an Off item. The selected frequency has fill and a visible ring; no tick. Station 4 is added end to end.

New On needs both round and station. Missing choices open a cancellable inline activation intention; Track stays Off, choices are persisted independently and the last required choice completes an atomic activation. The intention itself is ephemeral and cannot activate an item after reload. Off preserves its configuration. Existing On/null-station items are grandfathered without assigning or turning them off; unrelated changes continue to work. A valid active station cannot be cleared. Explicitly turning a grandfathered row Off removes the exception on its next activation. Legacy write endpoints enforce the same safety rules while replaying previously accepted IDs before new validation.

The six-column desktop table becomes a compact mobile row. Touch targets are 44px, names wrap and reduced-motion removes transitions without removing selection rings. Changed rows excluded by a current filter are retained until the user reapplies filters; filter changes remain explicit. Next evening check and catalog Add/Remove controls are removed only from this management surface. Check rounds' layout and all chef workflows remain unchanged apart from Station 4 compatibility.

## Commands, revisions and recovery

`/api/stock-settings` returns a single aggregate configuration and shared round days. Commands carry immutable UUID, account, client metadata, exact before values and independent stock/round/station revisions. One D1 batch conditionally inserts a receipt, history, station and stock/round changes. Station is written in the same transaction as activation. Existing `stock_commands`, activity and timeline tables are reused; there is no schema migration or operational assignment migration.

A per-account/item-operation localStorage journal is written before accepting UI changes. One writer drains immutable requests; rapid changes predict successive revisions. A lost result retries the original UUID. Individual rejected rows retain intended/shared choices without blocking other rows. Reapplication checks that the shared values shown during review are still current; replacement recovery is persisted before superseded entries are removed. Removed/merged identities retain a recovery card with explicit Keep shared catalog. Undo changes Track only and is conditional on the exact configuration still being current. Semantic equality compares fields rather than JSON property order. Bad storage and account changes keep explicit errors; no false saved state. Old local stock/frequency/station recoveries are retained and resolved before management edits. Controls remain disabled until the old journal has been checked, and its pending recovery can never be reported as Settings confirmed. Background refresh does not block editing after initial recovery.

Manage list refreshes in aggregate on focus, visibility, relevant same-origin storage events, manual refresh and every 60 seconds while active. This is not a new live transport. Evening/Morning batch, compact ACK, cursor sync, offline recovery and background Finish are unchanged.

## Instructions, authorization and Station 4

`RoundInstruction`/`PrepInstructionEditor` remain the sole source with the existing 500-character limit, drafts, permissions, revision review, history and feedback. Expanded desktop editing uses a full-width second row. Details and feedback are available through More; clearing station is explicit and permitted only while Off. Historical check instructions and station snapshots are never rewritten.

Station 4 is supported in filters, bulk configuration, new check snapshots, grouping, shared Finish, history/source information, server CSV and complete private backup. An old browser without `X-Labula-Stations: 4` receives a recoverable 426 reload message only when station-4 records would otherwise be rendered by an old station renderer (stock, evening full/batch/sync, information, operations). CSV export and complete backup remain available without that header. Original write IDs and stored local work survive upgrade/replay. Morning tasks retain their existing model and reference their original evening source.

## Verification

All 78 regression scripts passed, including the previous 76. New scripts exercise actual Manage handlers, controller, route and SQLite transactions: independent Off settings, all 12 frequency/station combinations, activation/validation/legacy guards, grandfathering, excluded rows, stale CAS, atomic rollback, receipt replay, actor permissions, unchanged existing notebook/check snapshots, queued rapid changes, one writer, offline/lost ACK/reload, two-client conflict, a late ACK after a fresher peer snapshot, safe Undo, storage failure and removed identities. The UI regression also holds the legacy initial GET and verifies disabled controls and truthful recovery status. Following the final narrowly scoped defensive changes, the new tests and information/operations regressions were rerun; no broad test suite was rerun without changed inputs. TypeScript, lint and the official Sites production build are required before publication.

Browser QA uses a separate SQLite state with 80 synthetic catalog items and separate Owner/Manager origins. Desktop plus 320/390/430 iframe viewports, long names, More/detail/return, inline activation, instruction editing, bulk Station 4 including excluded items, two-manager conflicts and offline/reconnect were checked. Native macOS Reduce motion was temporarily enabled, computed transitions were 0s and selection remained visible; original preference was restored. No production settings, instructions, chef answers, Ready or access permissions were modified.

Measurement uses actual routes/SQLite, 80 items and artificial 150ms transport per request. Six rapid queued changes reached final server ACK in approximately 0.95s; an independent second client's explicit refresh took approximately 0.18s. Local controller acceptance was below 1ms with memory storage; browser localStorage-to-visible selection was observed at 17–34ms. These are isolated local results, not production latency or a proven speedup. Automatic Manage list freshness can wait up to 60s when it remains visible without focus/storage/manual refresh.
