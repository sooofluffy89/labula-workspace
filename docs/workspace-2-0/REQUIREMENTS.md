# Workspace 2.0 — implementation and acceptance matrix

Today and Menu are equally important. The adapter preserves existing menu content; all verification in this run uses synthetic data. Equality of the live production menu remains a protected release gate.
Implementation is tracked against the latest prompt, not against the old
thirteen-section navigation. A status becomes **verified** only after the
named behavior is exercised; a source edit or prototype is not layout evidence.

Final implementation matrix. **Verified** refers to the specified automated or
Chromium evidence, never to a physical device or production deployment.
See [implementation report](IMPLEMENTATION.md), [browser results](evidence/browser-results.json)
and [validation result](evidence/validation-result.json).

## Verification labels

- **Automated**: executed regression script or reproducible browser assertion.
- **Browser reviewed**: actual rendered application inspected visually.
- **Emulated**: viewport, coarse pointer, reduced motion, zoom or reduced-height
  simulation; not a physical kitchen device.
- **Pending production**: protected current-menu comparison, maintenance gate,
  device draft inventory, deployment and live operational smoke tests.

Keep exact run commands, source commit, synthetic fixture identity, screenshot
dimensions and failures/limits in the final evidence report. Never relabel a
design prototype screenshot as an implemented application screenshot.
